# 图片上传与画廊发布

图片先成为私有媒体资产，随后被画廊作品引用。上传成功不代表图片已公开。当前每个作品只使用一张图片，正文中的通用附件和相册功能未提供。

## 上传一张图片

1. 使用有内容创建权限的账号，从“内容管理 → 媒体资产”进入上传页。
2. 选择自己有权使用的 JPEG、静态 PNG 或静态 WebP，文件不超过 10 MiB。动画、无法完整解码和超出像素/边长限制的文件会被拒绝。
3. 上传成功后记录资产 ID。系统生成 `display/detail/list/thumbnail` 四种 WebP，移除元数据并转换色彩空间，**不保留原始图片**；原件应由你另行保存。
4. 到“内容管理 → 协会画廊”新建作品，选择刚上传的媒体资产，填写作品标题、替代文本和可选摘要。
5. 作者默认当前账号；只有账号管理员可选其他作者。“公开笔名”可选，未填写时公开署名使用作者当时的显示名。
6. 核实后勾选“已确认作品展示权利”，按实际情况选择“无可识别人像”或“已确认人物同意”。保存草稿并复核，再发布。
7. 打开 Web `/gallery`、作品详情及图片，核对署名、替代文本和展示效果。

## 修改、下线与恢复

换图需重新上传资产，在作品中选择新图并保存草稿。访客继续看到旧公开版本，直到发布变更。署名是发布时的快照，改账号显示名不会悄悄修改旧公开署名。

下线作品后，该作品的详情和图片入口返回 404；其他仍公开作品的图片入口不受影响。已被下载的副本无法召回。资产不支持就地替换或日常物理删除；没有自动孤儿图片清理，容量增长需自行观察。

## 存储配置

本机试用由 `demo:init` 配置：

```dotenv
MEDIA_STORAGE_MODE=local
MEDIA_LOCAL_ROOT=/absolute/private/media-directory
```

目录必须可写且不在静态公开目录中。切换存储模式不会自动迁移旧图片，应先备份并制定迁移步骤。

使用 S3-compatible 存储时，删除 local 专用变量并提供完整配置：

```dotenv
MEDIA_STORAGE_MODE=s3
MEDIA_S3_ENDPOINT=https://your-private-endpoint.example
MEDIA_S3_REGION=your-region
MEDIA_S3_BUCKET=your-private-bucket
MEDIA_S3_ACCESS_KEY_ID=replace-with-application-access-key
MEDIA_S3_SECRET_ACCESS_KEY=replace-with-application-secret
MEDIA_S3_FORCE_PATH_STYLE=false
```

bucket 保持私有，应用账号只授予该 bucket 所需的列举、读、写及补偿删除权限。是否 path-style 由存储供应商决定。不要在 Web 中使用对象存储地址或公开 bucket；公开图片通过受控路由读取。

本机 S3 集成设施可运行 `docker compose up -d --wait postgres minio`，再 `docker compose run --rm minio-init`。MinIO API 为 `127.0.0.1:19000`，控制台为 `127.0.0.1:19001`；示例凭据仅供隔离测试。该 Compose 的 MinIO 初始化使用测试 root 账号，不能用作真实环境的权限配置模板。

## 故障与备份

- 400：检查图片类型/动画/尺寸、替代文本和发布权利确认。
- 413：制作小于 10 MiB 的展示图后重试。
- 401/403：重新登录或请管理员检查账号与权限。
- 404：确认作品仍公开、链接及图片尺寸名称正确。
- 503 或有框无图：检查媒体目录权限或存储连接与对象是否存在，保存请求编号；不要公开对象地址排错。

PostgreSQL 中的资产记录和媒体文件必须处于同一个恢复点，步骤见[备份说明](README.md#保存和恢复本机测试数据)。恢复后检查四种图片及草稿/下线作品仍不公开。单独备份数据库不能恢复图片。真实供应商兼容、容量告警和恢复演练仍需部署者验证。
